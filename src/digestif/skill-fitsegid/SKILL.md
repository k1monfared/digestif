# Fitsegid

Fitsegid is `digestif` reversed, letter for letter. Digestif reads a text and condenses it into a rooted, cited idea graph. Fitsegid reads that graph and tells it back as prose: the main points, the reasons under them, the evidence, the objections and rebuttals, in an order a reader can follow, with no filler and nothing invented.

The graph already holds everything prose usually gets wrong. The `contains` tree gives the order, the node types give each sentence its role, and the cross edges give the connectives. Fitsegid's job is to choose words that carry exactly what the nodes carry, no more and no less.

## Artifacts and the iron rule

One run produces two files:

```
name.fitsegid.md         cited prose, the only file the LLM writes
name.fitsegid-clean.md   the reading copy, generated by strip-prose, never hand-written
```

The input is `name.graph.json` (preferred, produced by digestif and already validated) or `name.outline.log` (the loglog outline, parsed when the graph is not at hand).

The iron rule: `fitsegid.md` is the only file you write. Never edit the graph, the outline, the viewer, or the clean copy. `scripts/fitsegid.py` proves that the prose is grounded, and it generates the clean copy.

All commands run from the skill directory:

```bash
python3 scripts/fitsegid.py check-prose name.fitsegid.md name.graph.json
python3 scripts/fitsegid.py check-prose name.fitsegid.md --outline name.outline.log
python3 scripts/fitsegid.py check-prose name.fitsegid.md name.graph.json --strict
python3 scripts/fitsegid.py strip-prose name.fitsegid.md
python3 scripts/fitsegid.py render name.fitsegid.md name.graph.json -o name.fitsegid.html
```

`check-prose` exits 1 on any error. `strip-prose` writes `name.fitsegid-clean.md` by default. `render` builds the two-pane review viewer, prose on the left and an expandable dendrogram on the right, for evaluating how well the prose maps onto the graph.

## The citation contract

Every sentence ends with the node ids it is built from:

```
Cities should ban cars from their centers. [1] Critics argue that car bans hurt businesses. [1.1]
Retail revenue rose in Madrid and Oslo after restrictions. [1.1.1, 1.1]
```

- One idea per sentence, so one or a few adjacent citations per sentence.
- A sentence with no citation is an orphan. The checker rejects it. There is no room for atmospheric or transitional sentences that assert nothing.
- Cite a node where its content actually appears. A citation is a claim that this sentence restates, condenses, or directly uses that node, nothing else.
- The root summary node `[0]` carries the thesis sentence.

## The frontmatter manifest

The file opens with a manifest the checker reads:

```
---
skill: fitsegid
lod: max
dropped: []
---
```

- `lod` is the level of detail requested: `max`, or a whole number of layers.
- `dropped` lists every node that intentionally does not appear in the prose. For `lod: max` it must be `[]`.

## Level of detail

The user states how much they want, in any of three forms. The default is maximum: lossless, every node realized.

- **Layers**: `lod: N` means go down N layers below the summary. `lod: 1` keeps the summary and the main points, `lod: 2` adds the details layer, and so on. Nodes deeper than N must be listed in `dropped`, and no cited node may be deeper than N.
- **Length budget**: a word target. Choose which branches to compress so the text lands near the target. Compress a branch by dropping its lower nodes and letting the parent sentence carry the point, then list the dropped nodes.
- **Detail level**: a plain description of how much to keep. Apply the same rule.

Whatever the form, the mechanism is one: every node is either cited or listed in `dropped`. Nothing disappears silently. Do not drop a parent while keeping its children.

## Building the prose

Read the graph first. Then plan, then write.

### Order

Walk the tree depth first, in id order: root, then `1`, then `1.1`, `1.1.1`, then `1.2`, then `2`, and so on. The root summary opens the text. Each main point (a child of the root) starts a paragraph or a section. Its subtree fills that paragraph. Never cite a node before its parent.

### Sentence roles from node types

- `summary` (root): the opening thesis.
- `theme`: a topic sentence when the text has no argument.
- `claim`: a topic sentence or a supporting assertion.
- `evidence`: a factual sentence under the claim it supports.
- `example`: a sentence introduced with "for instance", "for example", "such as".
- `counterpoint`: state it as someone else's position, never as the author's: "critics argue", "one objection is".
- `rebuttal`: follow the objection it answers, introduced with "but", "however", "the objection fails", "that claim does not survive".
- `concession`: "admittedly", "it is true that", "that may be true".
- `nuance`: attach it to the claim it qualifies, with "though", "provided that", "in that case".
- `contradiction`: state both sides and leave the tension visible.
- `implicit`: hedge it as the graph hedges it, "the text suggests", "this implies".

### Connectives from edge types

Cross edges are the only licence for glue text. Use the connective that matches the edge and no other.

| Edge | Connective |
| --- | --- |
| supports | because, since, this is why |
| exemplifies | for instance, for example |
| contradicts | against this, but, on the other hand |
| qualifies | provided that, though, only if, to the extent that |
| concedes | admittedly, it is true that |
| precondition | only once, only after, requires first |
| restates | merge the two nodes into one sentence, never repeat |

A cross edge whose endpoints land in different paragraphs is placed where its `from` node is cited. Do not invent a relation the graph does not declare.

### No filler

State, do not announce. No "in this essay", "it is important to note", "as we have seen", "in conclusion". No sentence whose only job is to move to the next one. If a sentence does not carry a node, cut it or fold its content into a cited sentence.

## Verification

Two checks, in order.

1. **Mechanical**: run `check-prose` and clear every error. It rejects orphan sentences, citations to unknown or dropped nodes, any node neither cited nor listed in `dropped`, a layer count that contradicts the citations, and (with `--strict`) any warning. Warnings flag numbers and capitalized names that appear in a sentence but nowhere in its cited nodes or passages, and counter or conceded nodes used without attribution. Treat every warning as a real risk and fix it, even when it is not fatal: if a number or a name is not in the cited material, either cite the node that carries it or remove it.

2. **Fidelity**: re-read every sentence against the node text and, when the graph carries them, the cited passages. This is the judgment check the script cannot do, the inverse of digestif's own list:
   - Numbers: every number, date, count, percentage, and unit survives exactly, no rounding, no new figures.
   - Approximators: over, about, nearly, more than, around stay attached to their number.
   - Ranges stay wide and scoped figures stay scoped.
   - Hedges and conditionals: often, tend to, might, sometimes, if, unless survive. A hedged node stated as a flat fact is a defect.
   - Negations: not, never, no, without, except, only keep their polarity.
   - Scope and limiting adjectives: every, most, some, major, minor, credible match the node.
   - Attribution: a counter or conceded node is always voiced as such, never promoted to the author's claim.
   - No addition: the connective grammar is the only place words appear that the graph does not contain. A sentence that asserts more than its citations is a defect. Split it or narrow it.
   - No omission beyond the manifest: if a node is missing and not in `dropped`, either write it or list it.

## Worked example

Input `examples/car-ban.graph.json` (ten nodes, three cross edges, from digestif) and its prose `examples/car-ban.fitsegid.md`:

```bash
python3 scripts/fitsegid.py check-prose examples/car-ban.fitsegid.md examples/car-ban.graph.json
python3 scripts/fitsegid.py strip-prose examples/car-ban.fitsegid.md
```

The prose reads:

> Cities should ban cars from their centers, though only after public transit expands, since the business-harm and elitism objections do not hold. [0]
>
> Cities should ban cars from their centers. [1] Critics argue that car bans hurt businesses. [1.1] That objection does not survive the evidence: retail revenue rose in Madrid and Oslo after restrictions. [1.1.1, 1.1] Exemptions matter, however, because buses and delivery vehicles must keep moving or goods cannot reach shops. [1.2]
>
> Critics also claim that car bans only work in wealthy cities. [2] That may be true today. [2.1] The same objection was raised against bike lanes, which now succeed in Bogota and Jakarta and failed there too. [2.2]
>
> Public transit must expand before any ban takes effect. [3] A ban without transit is displacement, not improvement. [3.1]

Every node appears once, the counterpoints keep their `[counter]` voice, the concession keeps "may", and the `3 qualifies 1` edge becomes the opening "though only after".

## Edge cases

- **Graph with no argument**: `theme` nodes at the top layer. Write descriptive prose, do not manufacture a thesis.
- **Contradiction nodes**: present both positions and the conflict, do not resolve it.
- **Cycles or `restates` edges**: merge into one statement, never repeat the same point twice.
- **Outline input**: `--outline` recovers node ids, types, text, and attributions from `outline.log`. Passage text is not in the outline, so the number and name checks fall back to node text alone.
- **Large graph, short target**: reduce by layers first, then by branch. Always write the full `dropped` list.
